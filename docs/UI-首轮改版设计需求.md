# 达芬奇密码 AI 素材工作台

## 首轮 UI 改版设计需求

**版本**: v1.0  
**日期**: 2026-08-11  
**交付目标**: 为电商内容生产团队建立可落地的桌面端工作台设计语言，并完成 5 个核心页面的高保真设计。设计要服务于“商品素材 -> AI 创作 -> 任务产出 -> 复用”的日常闭环，不做营销官网风格。

## 1. 本轮范围

本轮只设计以下 5 个页面。弹窗、抽屉和结果态作为所在页面的必要状态交付，不单独计入页面数量。

| 优先级 | 页面 | 对应现有实现 | 解决的关键问题 |
| --- | --- | --- | --- |
| P0 | 工作台首页 | `src/components/Dashboard.tsx` | 让用户快速判断生产状态、找到可复用内容，并从正确入口开始创作。 |
| P0 | 创作助手 | `src/components/Assistant/AssistantPage.tsx` | 将“对话、上传参考素材、方案确认、进入任务”组织为清晰的引导流程。 |
| P0 | 新建图片任务 | `src/components/CreateImageTask/` | 降低三栏参数工作台的认知负担，让用户明确当前还缺什么、提交会生成什么。 |
| P0 | 任务列表与任务详情 | `src/components/TaskList.tsx`、`src/components/TaskDetailsDrawer.tsx` | 支持批次追踪、结果预览、审核、失败定位和基于结果继续创作。 |
| P1 | 产品中心 | `src/components/ProductManagePage.tsx`、`src/components/ProductFormDrawer.tsx` | 将商品、SKU、素材、生成历史组织为可维护且可直接进入创作的业务入口。 |

### 明确不在首轮范围

- 模板后台管理、数据复盘、模型/通道配置、字典与权限管理。
- 登录页、视频任务的独立深度改版。
- 新增业务字段、接口、权限或任务状态；本轮仅优化信息架构、视觉和交互表达。

## 2. 用户与主路径

主要用户是运营、设计和商品团队，他们需要高频批量生产电商图片/视频，并在生成后筛选、审核和复用素材。

```
工作台首页
  -> 创作助手（可选：先梳理需求与素材）
  -> 新建图片任务（选择主体素材、设置创作内容和模型参数）
  -> 任务列表 / 任务详情（查看进度、审核产出、基于结果继续创作）
  -> 产品中心（补充或维护商品与素材，再回到新建任务）
```

## 3. 每页设计要求

### 3.1 工作台首页

**目标**: 作为每日工作入口，而不是模板瀑布流的复制页。

- 首屏必须看到：待处理任务、生成中任务、最近产出、明确的新建创作入口。
- “模板营地”和“我的作品”保留，但应有清晰的使用场景差异：前者用于发现和复用，后者用于继续已有成果。
- 卡片优先展示真实可判断的信息：封面、类型、创建时间、状态、复用动作；弱化装饰性指标。
- 空状态必须引导到上传商品素材、发起创作或使用模板三种下一步之一。
- 必须设计加载、无内容、加载失败、任务异常待处理四种状态。

### 3.2 创作助手

**目标**: 让用户知道 AI 正在做什么，以及何时进入正式任务配置。

- 左侧会话、消息区、输入区的层级应清晰，避免整个页面像普通聊天工具。
- 附件/参考素材需能看到名称、媒体类型、移除和预览；素材选择器使用统一的资源选择组件。
- AI 处理过程应按“理解需求 -> 制定方案 -> 检查素材与参数 -> 提交生成 -> 完成作品”呈现状态，失败时给出可行动的恢复路径。
- 对于“继续到创建任务”的建议，必须说明将带入的素材、能力和参数，用户可确认或返回编辑。
- 必须设计：新会话、首次使用、处理中、处理失败、风险提示、生成结果 6 种状态。

### 3.3 新建图片任务

**目标**: 保留现有“主体素材 + 内容编排 + 参数与结果”的业务结构，但重新组织三栏优先级。

- 以 1440px 桌面为主画板。左栏为主体和参考素材，中栏为创作内容，右栏为模型参数、提交前校验与结果摘要。
- 用户应能一眼判断：已选主体素材、已匹配商品、缺失的必填项、本次生成的张数与输出规格。
- 右栏提交区应始终可见或稳定可达；不可把关键生成操作埋入滚动末尾。
- 将高级参数与常用参数分层，避免首次使用者面对长表单；动态能力参数需预留不同字段类型的通用样式。
- 素材选择、商品未匹配、提交前校验、生成中、生成成功、生成失败均需有明确状态。
- 不改变现有后端参数约定：`schemaParams` 原样提交，设计稿不能引入字段重命名或前端单位转换。

### 3.4 任务列表与任务详情

**目标**: 用户能在批次级别快速判断优先级，并在详情中完成结果处理。

- 列表主视图以批次为单位，保留图片/视频切换、状态筛选、搜索和刷新。
- 状态使用固定、可辨识的颜色和图标规则：生成中、待审核、已通过、已打回、失败；不能只依赖颜色区分。
- 表格需允许用户快速扫读商品、模板、提交时间、进度、结果数量和下一步动作；避免过多边框和无意义标签。
- 任务详情抽屉必须承载：产物预览、单项审核、失败原因、参数摘要、继续创作、素材入库等动作。
- 必须设计：首次加载骨架、空列表、批次展开/折叠、生成中轮询、失败、无权限动作、结果预览。

### 3.5 产品中心

**目标**: 让商品团队能维护可用于 AI 创作的事实与素材，而不是通用 CRM 表格。

- 主列表按 SPU/SKU 建立清晰层级，突出“是否可创作、已有素材数、最近产出、素材完整度”。
- 产品详情抽屉或详情页需要集中呈现：商品事实、SKU、输入素材、生成素材、创作历史和“开始创作”。
- 新建/编辑产品表单应把业务必填项、SKU、主图和素材关联分组，提供保存中、保存成功、校验失败状态。
- 从产品直接进入创作时，明确带入的是哪一个 SKU 与哪张主体图。
- 素材选择器作为全局复用组件：支持分类、来源、媒体类型、搜索、单选/多选、上传和空状态；不单独计页，但必须给出关键状态。

## 4. 视觉与组件原则

- 产品定位为内部生产工具：信息密度适中、操作优先、避免官网式大 Banner、装饰性渐变和大面积卡片堆叠。
- 延续现有暖白背景、深炭侧栏、陶土橙主色的方向，但重建颜色 token、文字层级、间距、边框和状态色的统一规则。
- 卡片仅用于有独立对象或明确层级的内容；页面区块不应全部做成悬浮卡片。
- 图标统一使用同一套描边和尺寸体系；按钮需有默认、悬停、按下、禁用、加载、键盘焦点状态。
- 所有状态信息同时使用文字/图标，不能只用红绿颜色表达。
- 数字、时间、任务数量等数据使用等宽数字，便于扫读和比较。
- 交付优先桌面端 1440px；同时给出 1280px 下三栏任务页的压缩规则，以及移动端底部导航与关键操作的响应规则，不要求本轮完整绘制每个移动端页面。

## 5. Figma 交付物与验收

### 必须交付

1. 1 个可复用的基础设计系统页面：颜色、字体、字号、间距、圆角、阴影、图标规格、栅格。
2. 表单、按钮、标签、Tab、筛选器、表格、卡片、抽屉、弹窗、通知、空/加载/错误状态等组件及其变体。
3. 上述 5 个页面的高保真正常态与第 3 节列出的关键状态。
4. 主闭环原型：从首页/助手进入创作，提交后进入任务详情，并从结果或产品页继续创作。
5. 带开发说明的 Figma 文件：组件命名、状态命名、间距/尺寸标注、图片/图标来源清晰可追溯。

### 验收标准

- 开发能直接从组件和页面标注实现，不需要猜测交互、状态或响应规则。
- 每个主要操作都有明确的成功、加载、失败与无数据表达。
- 设计不改变已有字段、页面权限、接口或 `schemaParams` 数据契约。
- 首次用户能在首页 10 秒内找到“开始创作”，在创建页判断是否具备提交条件，在任务详情找到下一步处理动作。

## 6. 设计师投放说明

寻找有 B 端工具、内容生产工具或复杂表单经验的设计师。评估作品时重点看信息层级、状态设计、复杂工作流和 Figma 组件治理，不以视觉海报感为主要标准。

首轮需求确认后提供：现有线上/本地页面截图、账号权限样例、真实但脱敏的商品和任务数据，以及本需求文档。设计师应先输出信息架构与视觉方向稿，确认后再进入 5 个页面的高保真设计。
