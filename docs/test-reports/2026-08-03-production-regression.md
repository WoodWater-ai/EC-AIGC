## 缺陷

### P0: 前端菜单与角色授权没有统一来源

- 现状：侧栏菜单在前端静态定义，只对“通道异步任务”“资源分类”作了 `管理员` 条件显示；系统配置、商品素材库、模板与数据模块没有按后端的角色菜单树逐项渲染。
- 风险：角色菜单配置页的授权结果与实际侧栏不一定一致。未知角色会在前端用户适配层回退显示为“管理员”，而用户列表又把所有非管理员统一标为“运营策划”；两处都会造成角色和菜单误判。
- 处理原则：前端只能根据后端下发的“当前用户菜单树 + 按钮权限码”决定可见性和可操作性；后端接口必须继续做最终鉴权，不能信任隐藏菜单。

### P1: 素材关联产品后不能自动带出产品

- 复现步骤：在资源中心选择一张已关联产品的主体素材或视频首帧素材。
- 实际结果：图片和视频任务页面都要求再次手动选择产品，商品事实、Prompt 变量和关联商品没有自动填充。
- 期望结果：素材只有一个有效关联产品时，应自动写入任务的 `productId`，展示“已由素材带入”的来源标识，并立即填充商品事实与 Prompt。用户无需重复选择。
- 影响：重复操作容易使素材和商品错配，后续生成、审核、模板和数据归因均会失真。

### P1: 图片到视频的原生链路断开

- 复现步骤：完成图片生成并审核通过 -> 打开生成结果 -> 尝试从结果创建视频，或进入视频工作台的“视频首帧”资源中心搜索图片任务编号。
- 实际结果：图片结果页只提供“二次编辑”“设为模板”；视频首帧资源中心不包含该结果。
- 期望结果：审核通过的图片结果应提供“创建视频”操作，或自动同步到视频首帧可选资源，且带入商品、首帧和关联任务信息。
- 影响：用户无法完成“模特生成 -> 图片生成 -> 视频生成”的连续生产，只能改用已有资源或手工上传，丢失任务溯源和首帧一致性保障。

### P2: “生成提示词”没有填充必填最终 Prompt

- 复现步骤：在视频工作台填好产品和首帧后，点击“生成提示词”，再点击“检查并生成”。
- 实际结果：系统生成 3 条分镜，但“最终 Prompt”仍为空，提交提示“请输入本次视频 Prompt”。
- 期望结果：生成提示词应同步生成或组合填入最终 Prompt；若设计为仅生成分镜，应在 UI 上明确说明并取消最终 Prompt 的必填校验。
- 影响：视频生成工作流额外中断一次，需要用户手工补写 Prompt。

## 设计师与运营的推荐权限

权限按“菜单可见 + 按钮可执行 + 数据范围”三层定义。仅隐藏菜单不构成权限控制；每个接口仍须按 permission code 和数据范围校验。

| 业务域 | 设计师 | 运营 |
| --- | --- | --- |
| 工作台 | 查看本人和被分配任务、个人产出 | 查看团队生产看板、待审核和异常任务 |
| 图片/视频任务 | 新建、编辑、重试、取消本人任务；查看本人及被分配任务 | 新建、查看团队任务、催办/重试有授权任务；不可改写设计 Prompt 核心内容 |
| 结果编辑与审核 | 二次编辑本人结果；提交自检；不能终审本人结果 | 对团队结果评分、通过、打回、归档；不能二次编辑原始设计结果 |
| 素材库 | 浏览、上传、编辑本人素材标签；可使用已授权素材 | 浏览、上传、管理商品与素材关联；可纠正错误关联 |
| 模特库 | 浏览、创建与维护本人虚拟模特；用于图片/视频任务 | 浏览和使用；不修改人物设定、脸部锚点或授权声明 |
| 模板营地 | 浏览、做同款、创建/编辑“草稿模板” | 浏览、做同款、审核发布/下架模板；可查看模板使用数据 |
| 数据复盘 | 仅本人/项目数据，不导出全量明细 | 团队维度数据、导出运营报表、查看模板转化与审核效率 |
| 商品、分类、字典 | 只读产品信息和系统字典 | 产品素材关联可写；产品主数据、分类树和字典默认只读 |
| 系统、账号、角色、模型通道、异步任务 | 无权访问 | 无权访问 |

建议的权限码命名示例：`task:create`、`task:edit:own`、`task:review:team`、`asset:upload`、`asset:associate-product`、`model-profile:manage:own`、`template:draft:manage:own`、`template:publish`、`analytics:team:read`。数据范围应至少支持 `OWN`、`ASSIGNED`、`TEAM`、`ALL`，不要只靠角色名称判断。

## 素材自动带产品的目标交互

1. 用户在图片/视频任务中先选主体素材或首帧素材。
2. 系统读取素材的有效 `productIds`：
   - 仅 1 个：自动选择该产品，填充商品事实、主体图和 Prompt 变量，并显示“由素材带入”。
   - 0 个：保留“选择产品”；用户可先选产品再建立素材关联。
   - 多个：弹出候选产品选择，不允许静默猜测。
3. 用户已经手动选了不同产品时，必须提示冲突：改用素材关联产品、保留当前产品但标记“素材与产品不一致”、或取消选择素材。默认不允许直接提交不一致的主体素材任务。
4. 用户移除唯一主体素材时，只清除由该素材自动带入的产品；手动选择的产品不受影响。
5. 后端提交任务时重新验证“主体素材 - 产品 - 商品事实”关系，任务快照记录 `productSource=ASSET|MANUAL`、`assetProductRelationId`，确保审核、模板复用和数据归因可追溯。

验收用例：单产品素材自动填充；无关联素材保留手选；多产品素材弹出选择；素材与手选产品冲突拦截；模板复用后重新选择主体素材可自动刷新商品；视频首帧同样生效。

## 菜单重构建议

当前侧栏把创作、资产、模板、分析和系统运维平铺，同时“商品素材库”和“资源中心”重复，“通道异步任务、资源分类、商品分类、产品管理、字典”又散落在不同入口。建议按用户目标而不是后端表结构分组。

| 一级菜单 | 二级菜单 | 可见角色 | 调整说明 |
| --- | --- | --- | --- |
| 工作台 | 今日生产、待我处理、异常提醒 | 设计师、运营 | 首页只承载当天工作，不放管理功能。 |
| 创作 | 新建图片、新建视频、我的任务 | 设计师、运营 | “新建创作”保留为全局主按钮；任务列表移入本组。 |
| 生产管理 | 全部任务、审核队列、模板发布队列 | 运营 | 设计师不显示审核队列，减少误操作。 |
| 资产中心 | 素材库、产品素材关联、模特库 | 设计师、运营 | 合并“商品素材库”和“资源中心”；产品关联在同一资产域完成。 |
| 模板中心 | 模板营地、我的草稿、Prompt/参数库 | 设计师、运营 | 把“做同款”和“智能模板中心”统一为一个概念，避免用户分不清素材模板与 Prompt 模板。 |
| 数据复盘 | 我的产出、团队复盘、模板效果 | 设计师、运营（范围不同） | 设计师只看个人/项目，运营看团队与导出。 |
| 系统管理 | 账号与角色、模型通道、异步任务、产品主数据、分类与字典、审计日志 | 管理员 | 所有后台维护项只在此处出现，取消顶层散落入口。 |

桌面端一级菜单控制在 6 个以内；移动端只保留“工作台、创作、任务、资产、我的”五项，系统管理不进入底部导航。将“系统配置模块”改名为“系统管理”，“数据效能复盘”改名为“数据复盘”，“商品素材库”改名为“素材库”，减少技术化和重复命名。

## 其他优化项

| 优先级 | 项目 | 建议 |

| P1 | RBAC 落地 | 登录后拉取当前用户菜单树和按钮权限；侧栏、路由守卫、按钮状态使用同一权限 hook；接口鉴权单独保留。未知角色必须降级为无后台权限，不能回退管理员。 |
