# 达芬奇 AIGC 生产环境交互走查与优化报告

## 1. 结论

当前版本的主要问题不是某个页面“不够好看”，而是产品对象和工作流没有统一：商品、原始素材、生成任务、生成结果和模板分别出现在多套页面中，用户需要反复选择、跳转和重新确认上下文。

建议将产品从“后台模块集合”调整为“以商品项目为主线的创作工作台”：

```text
商品项目
├── 商品事实
├── 原始素材
├── 模特资产
├── 图片创作会话与结果
├── 视频创作会话与结果
└── 从优质结果沉淀的创作配方（模板）
```

本轮应优先处理 3 个核心机会：

1. **创作上下文连续**：素材已关联商品时自动带出商品，图片与视频统一；结果能继续生成视频或发起下一轮修改。
2. **生成留在当前页**：创作页右侧常驻结果区，承载排队、生成、预览、对比、失败、重试和多轮修改。
3. **统一模板概念**：合并首页“模板营地”和侧栏“智能模板中心”，将模板定义为可复用的 Prompt、参考图角色、模型参数和输出规格快照。

在以上问题完成前，不建议继续增加更多独立管理页面。新增入口会进一步加重用户判断成本。

## 4. 问题根因

### 4.1 同一个对象存在多套入口

```text
产品管理              管商品主数据
商品素材库            管商品、素材、生成结果、审核、成本
资源中心              管上传资源、公共/个人资源和分类
任务列表              管批次、子任务和结果
首页“我的作品”        再展示一次结果
首页“模板营地”        展示结果模板
智能模板中心          管另一套任务模板
```

用户无法回答三个最基本的问题：

- 我要找某个商品的全部素材和结果，应该去哪？
- 我看到的是原始素材、生成结果，还是已经发布的模板？
- 我修改、归档或打标签后，其他页面是否会同步？

### 4.2 分类、标签和业务归属混为一谈

- **商品归属**回答“这是哪个商品的内容”。
- **分类**回答“资产存放在哪个稳定目录”，通常为单选树。
- **标签**回答“它有什么特征”，应支持多选，如风格、场景、姿势、季节、渠道、审核结论。
- **任务类型**回答“为什么生成”，如商品主图、场景图、细节图、三视图。
- **状态**回答“当前处于哪个流程阶段”。

当前界面把以上字段分散到资源分类、商品分类、字典、模板标签和任务筛选中，且大量模板为“未标注”，因此用户看得到字段，却无法依靠字段完成检索和复用。

### 4.3 技术路由泄漏到创作层

创作者需要判断“最终模型是否适合当前任务、质量与速度如何、有哪些可调参数”，不需要理解 Provider、通道实例、异步能力和默认路由。技术路由应由管理员配置，由系统根据能力、成本、可用性和组织策略选择。

### 4.4 生成被设计成提交表单，而不是创作会话

当前链路是：填写表单 -> 提交 -> 离开页面 -> 到任务列表 -> 打开详情 -> 找结果 -> 再开弹窗修改。

设计师需要的链路是：配置 -> 生成 -> 原页等待 -> 查看大图 -> 对比 -> 追加修改 -> 得到新版本 -> 选优 -> 生成视频或沉淀模板。

## 5. 推荐信息架构

### 5.1 业务对象关系

```text
商品 Product
  ├─ 原始素材 Source Asset
  │    ├─ 商品图
  │    ├─ 参考图
  │    └─ 授权/来源信息
  ├─ 创作会话 Creation Session
  │    ├─ 图片任务与版本
  │    └─ 视频任务与版本
  ├─ 生成结果 Result
  │    ├─ 审核记录
  │    ├─ 评分
  │    └─ 是否晋升为可复用资产
  └─ 创作配方 Recipe Template
       ├─ Prompt 与变量
       ├─ 参考图角色
       ├─ 风格/场景/姿势标签
       ├─ 最终模型与可调参数
       └─ 输出规格与替换规则
```

生成结果不应被复制成多个不同对象。它始终属于来源商品和创作会话；审核通过后可以“晋升为资产”，设为模板后增加一条模板关联，原始溯源保持不变。

### 5.2 推荐菜单

| 一级菜单 | 二级页面 | 说明 |
| --- | --- | --- |
| 工作台 | 今日任务、待我处理、异常提醒 | 只回答“今天要做什么” |
| 创作 | 新建图片、新建视频、创作会话 | 新建入口与持续创作历史统一 |
| 商品项目 | 商品列表、商品工作区 | 商品是素材和结果的主要归属 |
| 资产中心 | 全部资产、模特、待整理 | 管可复用资产，不再混入任务队列 |
| 模板中心 | 团队模板、我的草稿、收藏 | 合并模板营地和智能模板中心 |
| 生产任务 | 全部任务、审核队列、异常任务 | 面向运营的跨项目队列 |
| 数据复盘 | 产能、质量、成本、模板效果 | 按角色控制数据范围 |
| 系统管理 | 账号角色、模型路由、分类标签、字典、日志 | 仅管理员可见，不出现在普通侧栏 |

普通角色的一级菜单控制在 6 个以内。资源分类、商品分类、产品管理、字典分类、字典管理、通道异步任务全部移入系统管理或合并到对应业务页面，不应与“工作台首页”同级。

## 6. 关键页面重构

### 6.1 商品工作区：解决多头管理

商品工作区应成为单一业务入口：

```text
┌ 商品：镂空装饰贝雷帽 ───────────────────────────────────┐
│ 商品事实  品类  状态  负责人                 [新建创作] │
├────────────────────────────────────────────────────────┤
│ 概览 │ 原始素材 │ 图片结果 │ 视频结果 │ 模板 │ 活动记录 │
├────────────────────────────────────────────────────────┤
│ 当前 Tab 内容                                           │
└────────────────────────────────────────────────────────┘
```

具体规则：

- 产品管理只保留为管理员的主数据维护能力，不再作为普通用户入口。
- 商品素材库的“商品卡片视图”升级为商品项目列表。
- 商品详情不使用窄抽屉，改为可分享、可返回、可保留筛选状态的完整页面。
- 图片与视频结果按创作会话和版本归组，默认展示最新优选结果。
- “任务列表”只负责跨项目的执行监控，不再成为找素材的主要入口。

### 6.2 资产中心：解决分类与标签缺失

资产中心建议使用三个业务视图，而不是“上传资源 / 商品素材 / 模特库”三个来源 Tab：

| 视图 | 默认分组 | 主要操作 |
| --- | --- | --- |
| 商品资产 | 商品 -> 原始素材/已晋升结果 | 查看商品、用于创作、修正关联 |
| 通用资产 | 分类树 + 标签筛选 | 上传、整理、批量打标、移动分类 |
| 模特资产 | 模特身份 -> 形象版本 | 创建模特、授权管理、用于创作 |

资源卡片至少显示：缩略图、资产名称、媒体类型、所属商品、来源、分类、关键标签、授权范围、审核状态和更新时间。默认不显示“公共/个人”作为唯一识别信息。

分类和标签规则：

- 每个资产最多一个主分类，可有多个业务标签。
- 风格、场景、姿势、季节、渠道作为标签维度展示为筛选组。
- 上传或生成后进入“待整理”，运营可批量补分类和标签。
- 无标签素材不隐藏，应有“未标注”治理队列和数量。
- 点击空分类时显示空状态、当前筛选条件和“清除筛选”，不能只留白。
- 资源选择器复用同一检索能力，但以轻量弹窗呈现，不承担资产管理功能。

### 6.3 创作页：左侧配置，右侧结果

推荐将图片和视频创作统一为同一交互骨架：

```text
┌ 创作上下文 ─────────────────────────────────────────────┐
│ 商品：镂空装饰贝雷帽  来源：由首帧素材自动带入  [更换] │
├──────────────────────────┬─────────────────────────────┤
│ 配置区 42%               │ 结果区 58%                  │
│                          │                             │
│ 主体/首帧/参考素材        │ 空态：配置完成后生成         │
│ 风格 · 场景 · 姿势标签    │ 等待：队列与预计阶段         │
│ Prompt / 修改要求        │ 生成：逐个结果占位与进度     │
│ 最终模型                 │ 完成：大图/视频与版本对比    │
│ 模型可配置参数           │ 失败：原因、建议和重试       │
│ 输出规格                 │                             │
│                          │ [继续修改] [生成视频]       │
│ [开始生成]               │ [晋升资产] [设为模板]       │
└──────────────────────────┴─────────────────────────────┘
```

提交后的行为：

1. 用户留在当前页面，右侧立即创建结果占位卡。
2. 服务端返回任务 ID 后开始轮询或订阅状态，刷新页面后仍恢复会话。
3. 多结果逐个到达，不等全部完成才展示。
4. 结果完成后默认大图预览，可在版本间切换和并排对比。
5. 用户输入下一轮修改要求，形成 `V1 -> V2 -> V3` 版本链；保留每轮 Prompt、蒙版和参数快照。
6. 用户可以离开页面，任务在后台继续；顶部任务中心显示进度，返回时恢复右侧结果。

结果区必须覆盖：未开始、Preflight、排队、生成中、部分成功、全部成功、生成失败、取消、超时、内容审核拦截和额度不足。

### 6.4 素材自动带商品

图片页已经能从“商品素材”自动匹配商品，视频页仍未同步。建议统一为底层规则，不允许两个创作类型分别实现：

1. 素材只有一个有效商品关联：自动填充商品和商品事实，显示“由素材带入”。
2. 素材无商品关联：商品改为非强制起点；用户可以继续创作，或手动选择商品并建立关联。
3. 素材关联多个商品：弹出候选商品，不静默猜测。
4. 已手选商品与素材关联冲突：提示“使用素材关联商品 / 保留当前商品 / 取消素材”，默认不允许无提示错配。
5. 图片结果进入“生成视频”时：自动带入来源商品、结果图、来源任务和比例。
6. 任务快照记录 `productSource=ASSET|MANUAL|NONE`，便于审计和数据归因。

视频页验收重点：选择本轮测试的“镂空装饰贝雷帽-PRODUCT_MAIN”后，顶部商品卡、商品事实和最终提交参数必须自动更新，不得继续显示“未填写”。

### 6.5 模型与参数：隐藏通道，保留最终模型

创作页只展示：

- 最终模型名称，例如“Vidu Q3 Turbo”。
- 适用说明，例如“动作稳定 / 速度优先 / 商品保真”。
- 质量、速度和成本的简短相对提示。
- 当前模型实际允许配置的参数，如比例、分辨率、时长、音视频直出。
- “推荐”标记和选择模型入口。

不展示：Provider、通道实例名称、能力编码、`async`、默认路由和实例健康状态。

后台继续保留“能力 -> 默认通道 -> 默认模型”的路由配置。前端根据模型的 `parameter_schema.fields[]` 动态渲染参数；切换模型时只保留兼容参数，并明确提示哪些参数已重置。

模型、风格、场景、姿势放在同一“创作控制”区域。默认展示推荐值，高级参数折叠。这样用户的判断顺序是“我要什么效果 -> 用哪个模型 -> 调哪些参数”，而不是先理解技术通道。

### 6.6 模板：从结果卡变成创作配方

模板应保存以下快照：

- Prompt、负面约束、变量和可编辑范围。
- 参考图及其角色：主体、模特、姿势、风格、场景、细节。
- 风格、场景、姿势、品类和适用渠道标签。
- 最终模型 ID、允许用户调整的参数和默认输出规格。
- 替换规则和保真约束。
- 来源结果、来源商品、创建人、版本、审核状态和效果数据。

模板详情必须在使用前回答：需要用户提供什么、会保留什么、会替换什么、将使用哪个模型、默认生成几张/几秒。当前只展示成片与“替换当前商品主体素材”不够。

统一后只保留一个模板中心：

- 团队模板：已审核，可直接使用。
- 我的草稿：从结果沉淀，待补标签或待审核。
- 收藏：个人快捷入口。
- 模板效果：使用次数、成功率、平均评分和成本。

首页只展示模板中心的推荐集合，不再维护另一套模板数据。侧栏“智能模板中心”的 3 个任务模板应迁移或映射到同一配方模型。

## 7. 优先级清单

### P0：阻断创作闭环

## 8. 角色菜单与权限建议

| 业务域 | 设计师 | 运营 |
| --- | --- | --- |
| 工作台 | 本人任务、被分配任务、个人结果 | 团队任务、待审核、异常和积压 |
| 创作 | 新建图片/视频、修改本人会话、重试本人任务 | 新建任务、分配任务、查看团队会话；不直接覆盖设计师原始版本 |
| 商品项目 | 查看授权商品及其素材/结果 | 创建和维护商品项目、负责人和素材关联 |
| 资产中心 | 浏览、上传、维护本人资产标签；使用授权素材 | 批量分类打标、修正商品关联、归档和治理 |
| 模特资产 | 创建和维护本人模特，使用授权模特 | 查看和使用；维护授权状态，不修改人物锚点 |
| 模板中心 | 使用、收藏、创建草稿、提交审核 | 审核、发布、下架、推荐和查看模板效果 |
| 审核 | 自检并提交，不终审本人结果 | 评分、通过、打回、归档和批量处理 |
| 数据复盘 | 本人/项目范围 | 团队范围、导出、模板和质量分析 |
| 系统管理 | 不可见 | 默认不可见；仅管理员角色可见 |

当前线上“设计”部门账号仍可能配置为“运营策划”角色，说明部门、岗位和系统角色需要解耦。菜单可见、按钮可执行、数据范围必须分别授权，不能仅用角色名称控制。

## 9. 状态与异常设计

### 9.1 创作任务状态

```text
DRAFT -> PREFLIGHT -> QUEUED -> RUNNING -> PARTIAL_SUCCESS -> SUCCEEDED
                         |          |              |
                         v          v              v
                      CANCELED    FAILED        REVIEW_PENDING
```

- `PREFLIGHT`：展示预计规格、费用、模型和输入冲突。
- `PARTIAL_SUCCESS`：部分结果先可用，失败项可单独重试。
- `FAILED`：展示用户可理解的原因和下一步，不只显示“服务端异常”。
- 刷新或离开页面后，状态和当前结果必须恢复。

### 9.2 关键反馈文案示例

| 场景 | 建议反馈 |
| --- | --- |
| 素材自动匹配商品 | “已由首帧素材带入商品：镂空装饰贝雷帽” |
| 素材与手选商品冲突 | “该素材属于 A，当前选择为 B。请选择使用 A、保留 B 或取消素材。” |
| 模型参数被重置 | “切换模型后，分辨率已从 2K 调整为该模型支持的 1080P。” |
| 模板缺少主体 | “模板已应用。还需选择 1 张商品主体素材。” |
| 部分生成失败 | “4 个结果已完成 3 个，1 个因内容审核未通过，可修改 Prompt 后重试。” |
| 后台继续生成 | “任务正在后台生成，可离开当前页面；完成后会通知你。” |

## 10. 迭代顺序

### 迭代 1：先修连续创作

- 统一图片/视频的素材带商品规则。
- 图片结果增加“生成视频”。
- 创作页增加右侧结果状态容器，先支持单轮生成和原页等待。
- 修复模板中心使用异常和错误返回导航。
- 创作页隐藏通道实例，只保留最终模型与参数。

### 迭代 2：统一对象和入口

- 建立商品工作区完整页面。
- 将商品素材库拆为商品项目与资产中心。
- 合并模板营地与智能模板中心。
- 重构普通角色菜单，后台配置全部移入系统管理。

### 迭代 3：提升规模化生产

- 多轮会话、版本比较和回退。
- 批量分类打标、未标注治理和容量治理。
- 审核队列、模板效果和质量成本复盘。
- 完整落地按钮权限与数据范围。
