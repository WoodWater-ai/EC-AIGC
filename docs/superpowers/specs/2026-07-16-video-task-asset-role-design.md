# 视频任务素材角色统一设计

日期：2026-07-16  
状态：已实施（前端 Mock）  
范围：新建视频任务页面与资源中心选择器的 Mock 交互

## 1. 目标与判断

视频生成的必要输入只有三类：

1. 要被保真的主体或开场画面。
2. 需要参考的视觉信息。
3. 用户希望画面如何运动和表达。

因此，任务页不应同时存在“参考图”和“选择模特”两个输入入口。模特图本质上也是一张参考图，只是角色为 `model`。每一张图片只选择一次、只在一个清单中出现，并明确它在生成中的角色和优先级。

爆款复刻的源视频是可追溯的业务资产，不是临时本地文件。它也必须从资源中心选择，以获得文件 ID、缩略图、时长、来源和授权状态。

## 2. 页面结构

保留图片任务已使用的三栏工作台，不增加向导或独立模特面板：

| 区域 | 职责 | 不承担的职责 |
| --- | --- | --- |
| 左栏：输入素材 | 从资源中心选视频或图片，标记每张图片角色、排序、移除 | 不编辑 Prompt，不选择模型 |
| 中栏：任务配置 | 模式、时长、比例、分辨率、运动幅度、Prompt、负面约束、时长驱动分镜 | 不重复展示模型能力 |
| 右栏：模型能力 | 通道和模型、当前规格支持情况、参考图上限、成本、健康度、额度和风险 | 不再提供任务规格输入或独立模特选择 |

模型能力决定中栏业务参数可选项。切换模型或应用预设导致不兼容时，展示冲突及替代项；用户确认后才修改任务配置。

## 3. 统一图片素材清单

### 3.1 数据模型

视频页面所有图片统一使用下列前端对象。真实接入时映射为 API 契约中的 `{ asset_id, role, position }`，不得把页面对象作为后端 DTO。

```ts
interface VideoInputAsset {
  id: string;
  name: string;
  url: string;
  source: string;
  role: 'first_frame' | 'product' | 'model' | 'style' | 'scene' | 'action';
  position: number;
}
```

角色含义：

| 角色 | 用途 | 约束 |
| --- | --- | --- |
| `first_frame` | 锁定开场构图和主体位置 | 参考生视频必须且只能有一张；图生视频唯一图片默认此角色。 |
| `product` | 保真商品的颜色、结构、材质或细节 | 可选，可多张。 |
| `model` | 模特脸型、身材比例、体态或姿势参考 | 可选，可多张；替代页面级“选择模特”。 |
| `style` | 色调、光影、镜头质感 | 可选，可多张。 |
| `scene` | 场景、环境和布光 | 可选，可多张。 |
| `action` | 动作、机位、镜头运动 | 可选，可多张。 |

选择图片后，默认角色按资源分类或标签推断，用户可通过卡片内下拉框修改。每个卡片显示缩略图、名称、来源、角色、顺序和移除按钮；顺序通过上移/下移保持连续，不引入拖拽依赖。

### 3.2 模特资源库的定位

保留“模特资源库”用于维护虚拟/授权模特资料和在资源中心按“模特”分类过滤。视频任务页删除独立的模特选择状态、模特下拉和拼接 Prompt 的逻辑。

未来若需要“推荐模特”，推荐结果只作为“添加为模特参考”的快捷入口：确认后向统一图片清单添加一项 `role: model`，不产生第二份选择数据。

## 4. 三种模式的最短路径

### 4.1 图生视频 `img2video`

1. 从资源中心选择一张图片。
2. 该图片自动成为 `first_frame`，页面展示任务配置和 Prompt。
3. 选择业务规格、确认 Prompt 后提交。

本模式不展示多参考图区，也不展示模特选择。需要人物或场景控制时，用户应切换到参考生视频。

### 4.2 参考生视频 `reference2video`

1. 从资源中心选择多张图片。
2. 在同一清单中标记一张为 `first_frame`，其余标记为商品、模特、风格、场景或动作/镜头。
3. 系统校验首帧唯一、总数量不超过当前模型上限、角色与模型能力兼容。
4. 分析素材冲突和运动风险，生成或补充 Prompt；用户确认后提交。

提交条件：恰好一张首帧，且至少有一张额外参考图。这样“参考生视频”与单图生视频的价值边界清晰。

### 4.3 爆款复刻 `trending_replicate`

1. 点击“资源中心”选择复刻源视频，资源中心只显示 `assetKind=VIDEO`；也可在同一卡片输入可访问的视频链接。
2. 链接导入先创建只绑定当前任务草稿的 `temporary` 视频资产。后端校验协议、可访问性、媒体类型和大小后，下载到私有存储并提取封面、时长和校验值；导入完成前不能分析。
3. 选择或导入完成后显示封面、名称、时长、来源和授权状态。链接导入默认不进入可搜索的资源中心，用户后续可明确选择保存为正式资源。
4. 点击“添加替换素材”，资源中心只显示 `assetKind=IMAGE`；在统一清单中标记为 `product`、`model`、`scene`、`style` 或 `action`。
5. 至少有一个 `product` 替换素材时，允许分析原视频的关键帧、节奏、爆点、替换策略和风险。
6. 用户确认分析生成的 Prompt、规格和模型后提交。

不提供浏览器本地上传。链接导入由后端归档为任务暂存资产，避免外链失效、内容替换、权限绕过和模型读取失败。

## 5. 去重与渐进展示

- 时长、比例、分辨率、运动幅度只在中栏“任务配置”编辑一次；右栏仅展示模型是否支持当前选择。
- 用户未完成必要素材选择前，只显示素材区和简短的下一步提示，不展示长 Prompt、分镜和无效的提交按钮。
- 素材齐全后，展示任务级 Prompt、负面约束和时长驱动分镜。切换时长只新增缺失分镜建议，不覆盖用户已编辑的内容。
- 任务顶部提交按钮在未满足条件时显示明确缺失项，例如“请选择首帧”或“爆款复刻需要商品替换素材”，而不是只置灰。
- 图片角色、素材顺序、模型或业务规格变化时，标记分析、Prompt、Preflight 和执行确认失效；真实 API 模式按五步任务组契约重新确认。

## 6. 资源中心和数据对齐

资源选择器新增或确认以下槽位行为：

| 槽位 | 可选资产 | 是否多选 | 筛选 |
| --- | --- | --- | --- |
| `video-first-frame` | 图片 | 否 | `assetKind=IMAGE` |
| `video-reference` | 图片 | 是 | `assetKind=IMAGE` |
| `trending-source-video` | 视频 | 否 | `assetKind=VIDEO` |
| `trending-replacement` | 图片 | 是 | `assetKind=IMAGE` |

资源中心回传完整 `AssetResourceItem`。视频页使用 `productAssetId` 关联商品，不再按文件名反推；Mock 数据需提供至少一个可选视频资源及其缩略图、时长、来源和授权展示字段。

## 7. 验收标准

1. 视频任务页面不再出现独立“模特选择”或 `selectedProfileId` 状态。
2. 从资源中心选择模特图片并标记为“模特”后，该图片参与 Prompt、上下文分析和有序参考资产请求。
3. `reference2video` 无首帧、多个首帧、无额外参考图或超出模型上限时均不可提交，并给出对应原因。
4. `img2video` 只需一张首帧图片，不显示参考图或模特冗余入口。
5. 爆款复刻可从资源中心选择一个视频源，或导入一个 `http/https` 视频链接；不提供浏览器本地上传。链接导入完成前不可分析或提交，且默认不进入资源中心。
6. 爆款复刻至少选择一张商品替换图后才可执行分析；模特、场景、风格和动作图均是可选替换参考。
7. 改变图片角色、顺序、模型或业务规格后，前端显示需要重新分析/确认的状态；真实接入后按 V2.3 任务组状态机处理。

## 8. 本轮不做

- 不改资源中心的上传、分类维护或素材库管理流程。
- 不做在线视频 URL 导入、网页抓取或本地临时文件直传。
- 不做复杂分镜剪辑、镜头拖拽时间线或自动成片。
- 不接真实后端 API、模型服务或付费生成。
