# 批次任务结果工作台设计

## 目标

让运营能从一个批次快速判断每类图片的生成结果、审核状态和下一步动作；对任意单张图继续编辑时，完整继承此前的生成、编辑和审核上下文。

当前页面的核心问题是：批次信息被拆成多个任务行，详情中又被概览、输入、产物等标签拆散；结果图不完整，打回状态可能没有图片，且当前 mock 的商品名与睡裙图片不一致。

## 范围

本次仅调整前端 SPA 的任务列表、详情侧边抽屉和 mock 数据。飞书不作为运行时数据源；其本地导出缓存只作为可复现 mock 素材的来源。后端、数据库和正式接口均不在本次范围。

## 列表

- 列表一级行是批次，不再是一条生成子任务。
- 批次显示唯一提交时间 `submittedAt`；没有该字段时显示“未提交”，不回退到创建时间。
- 批次状态由子任务汇总：存在进行中任务时为“进行中”；全失败为“失败”；存在待审核或打回结果时为“待处理”；全部已通过时为“已完成”。
- 左侧小三角用于展开/收起。展开后显示二级行，每行对应一个图片类型，包含类型名称、子任务状态和产物数量。
- 点击批次或二级行均打开同一个批次详情侧边抽屉；二级行同时选中对应图片类型。
- 列表和详情中的任意结果缩略图均可点击放大预览。

## 详情侧边抽屉：结果工作台

详情抽屉不再使用“概览 / 输入素材 / 本批次产物 / 评分记录 / 成本”的并列标签。抽屉固定为两栏：

- 左栏是图片类型导航，逐项显示状态、产物数量和是否有待处理结果。
- 右栏是当前图片类型的工作区，默认选中用户从列表进入的类型，否则选中批次的第一个类型。
- 顶部只保留批次识别信息：商品、批次号、提交时间和子任务数。
- 移除“切换为当前类型”。选中左栏图片类型即完成切换。

当前类型工作区按使用频率排列：

1. 结果区：完整显示该类型的所有版本和候选图，不截断。
2. 结果卡：图片、版本、审核状态、审核意见、二次编辑、评分审核和创建视频（仅已通过图片）。
3. 可折叠的“本次输入与最终提示词”面板：商品主体、参考素材、最终 Prompt、负面约束、模型和关键参数。这里展示的是本次任务实际提交的 Prompt 副本，不是模板原文。
4. 可折叠的“审核与版本记录”面板：按时间展示审核决策、评分、标签和编辑版本关系。

结果图点击后打开居中预览层，支持前后切换、缩放、下载入口和关闭。预览层只浏览当前图片类型的全部结果，避免跨类型误操作。

## 打回与二次编辑

- 打回是“结果状态”，不是“无结果”。每个打回结果必须保留原图、具体打回意见和继续编辑入口。
- 二次编辑基于某一个结果版本创建子版本，不创建新的顶级任务或独立对话。
- 编辑对话展示不可编辑的继承上下文：初始 Prompt、负面约束、商品保真规则、历史编辑指令、遮罩和审核意见。
- 新增编辑指令只追加为下一轮上下文。保存后生成新的候选版本，并与父版本建立 `parentImageId` 关系。
- 因而每张图可沿版本链追溯到初始生成，避免编辑请求丢失商品事实、前序修改和审核要求。

## 数据与组件边界

- `GenerationTask` 继续承载批次子任务及输入、提示词和结果版本。
- `GeneratedImageResult` 增加来源追踪字段，并继续使用 `revisionContext` 保存不可变的编辑上下文链。
- `TaskList` 只负责批次聚合、展开和打开详情。
- `TaskDetailsDrawer` 只负责已选批次的类型导航、结果工作区、预览、审核和编辑交互。
- 图片预览层应抽为独立组件，供列表与详情复用，避免两套缩放和切换逻辑。

## 异常与空状态

- 生成中：显示进度和已产生的中间结果（若有）。
- 生成失败：显示错误说明和重试入口，不伪造结果图。
- 尚无结果：只在任务尚未生成过时显示；已打回任务不进入此状态。
- 无提交时间：显示“未提交”，不以任务创建时间替代。

## 验证标准

- 一个批次只在列表中出现一次，展开后能看到所有图片类型。
- 批次与二级类型进入详情时，选中状态正确。
- 当前类型的全部结果均展示并能放大预览。
- 打回图保留图片、意见和二次编辑入口。
- 最终 Prompt 在当前类型工作区可见。
- 二次编辑后的新版本保留原始 Prompt、负面约束、历史编辑和审核意见。
- mock 素材不再出现商品名与图片类型不一致。
